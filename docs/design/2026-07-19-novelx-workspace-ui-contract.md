本文是后续前端实施的设计契约。实施时先遵守“最终决定”，再参考逐字讨论记录和图片；逐字记录中的早期提案若被后续对话推翻，不得恢复为产品行为。

本文包含两种证据：

1. **最终决定**：用户已明确同意，或已明确纠正后的当前产品定义。
2. **逐字讨论记录**：从本地 Codex 会话日志机械抽取的用户与助手可见文字，用于追溯语境。图片二进制、工具调用、内部系统消息和开发者消息不属于产品对话，未写入逐字区；图片以仓库中的参考资产文件保留。

本文不是实现证据。没有真实状态接入、持久化、失败路径与桌面运行验收时，不得把静态页面或 Mock（模拟）称为已完成能力。

逐字区有一处来自原始用户消息的行尾空格。为满足逐字留档要求，该空格有意保留，因此对本文直接执行 `git diff --check` 会报告这一处；这不是未清理的格式错误。逐字区使用日志重建后的逐字符比较单独验收，其他文件仍须通过常规格式检查。

## 2. 当前实施目标、边界与停止条件

### 2.1 当前可进入的目标

先搭建经过确认的前端骨架：单层外壳、左右折叠、项目与会话导航、主页与六类资源工作面的布局状态、真实可操作的页面切换、面板展开/收起和必要的状态占位。视觉语言应以参考图为依据，暖色、低彩度、线性符号、轻边界，不给 Agent（智能体）设置五颜六色的按钮。

### 2.2 本批骨架不等于完成的能力

- 不把静态 Growth 状态冒充真实运行链。
- 不把示例文件、示例图谱、示例地图或本地模板冒充真实项目数据。
- 不在 UI 批次中擅自修改公开协议、领域数据模型、权限、Canon（正史）语义或 Runtime（运行时）所有权。
- 不在未确认详细规则前实现响应式阈值、完整动画参数、弹窗系统、全部空/错/权限状态和各页最终工具栏。
- 不承诺在“骨架”批次内完成任意地图自动解析、多级 Atlas（图册）数据生产、图谱检索后端或完整世界包导入导出。

### 2.3 验收原则

- 真实 Electron（桌面壳）中只有一层 NovelX 外壳。
- 每个已实现的切换、折叠、恢复和拖动规则可实际操作，不是截图。
- 页面切换不丢失已要求保存的项目位置、会话草稿和面板状态。
- 不允许用固定演示数据宣称真实 Growth、Provider（模型服务）或项目写入已接通。
- 每个阶段完成后覆盖桌面正式预览，并以真实窗口截图核对参考图和本契约。

## 3. 最终决定

### 3.1 六类资源与唯一外壳

最右侧固定六个资源入口：

1. 文件
2. 世界
3. 角色
4. 图谱
5. 故事
6. 世界包

NovelX 只有一层共享外壳。顶栏和左侧使用同一背景色，视觉上融为一体；不得再出现两个 NovelX 标题栏或一层软件壳套另一层工具栏。顶栏中央只显示一个可点击的 `NovelX`，点击后回到当前项目主页。顶栏左、右分别提供侧栏折叠控制。窗口最小化、最大化和关闭继续使用 Windows 原生右侧控制，不采用仿 macOS 红绿灯。

### 3.2 主布局与六工作面的切换

没有资源展开时，默认是项目主页：左侧项目/会话区，中间主对话，右侧紧凑文件区，六图标固定在最右侧。

点击任一资源图标后：

- 对应工作面在中间展开。
- 原主对话缩成左侧小对话栏，保留同一个会话、历史、草稿和流式状态。
- 再次点击当前图标，工作面缩回，恢复项目主页与右侧紧凑文件区。
- 点击另一个图标，在原位置直接切换工作面，不先收回主页。
- 六图标始终固定在最右侧，不随工作面移动。

右侧存在三个稳定状态：仅图标、默认紧凑文件区、资源工作面展开。顶栏右侧折叠键可把整个右侧内容折成仅图标；从资源展开态恢复默认时回到紧凑文件区。

六个资源工作面共用以下骨架：

```text
项目方块栏 | 小对话栏 | 资源导航器 | 主工作面 | 条件式详情栏 | 六图标栏
```

详情栏只有在选中对象时出现。用户手动收起详情栏后，切换选中对象不得强制重新打开；用户再次打开时显示当前选中对象。

### 3.3 左侧项目与会话

展开状态参考 OpenCode：多个项目可以同时展开，也可以只展开一个。项目和会话都可以置顶；置顶只创建快捷入口，不改变真实层级和原位置，项目快捷方式与会话快捷方式可以混排。

排序只使用直接拖动：

- 不增加上移/下移菜单。
- 不增加键盘排序。
- 项目之间可以拖动排序。
- 会话只能在所属项目内拖动排序，不能跨项目。

左侧收起后成为项目方块栏：一个方块代表一个项目；存在世界包封面时使用其方形裁切作为方块封面，没有封面时使用克制的默认符号。点击项目方块直接切换项目并恢复该项目“上次位置”。

每个项目保存独立 Workspace Snapshot（工作区快照），至少包括：上次会话或资源页、当前选择、滚动位置、面板宽度与折叠状态、输入草稿和 Growth 查看位置。折叠后的项目方块栏不显示置顶会话；置顶快捷方式只在完整项目栏中显示。

项目主页打开完整左栏时采用推挤布局。资源工作面中，完整项目栏默认折成项目方块栏；点击顶栏左侧按钮后，以覆盖层展开完整项目栏，覆盖小对话栏，不挤压主资源工作面。

### 3.4 主对话与小对话栏

小对话栏不是另开一个聊天组件或新会话，而是当前会话的紧凑投影，必须保留：

- 完整消息历史与当前流式输出。
- 输入草稿。
- 当前对象上下文。
- 等待用户处理的决定；待处理决定固定在输入框上方。

小对话栏可调整宽度，也可完全折成图标宽状态；折叠状态仍显示运行、等待或失败状态。消息视觉采用：用户消息为浅暖色紧凑块，NovelX/Agent 回复为无外框正文，工具活动为可展开的折叠行。输入区继续保留“协助 / 自由”，并提供发送/停止、上下文提示和自然滚动控制。

### 3.5 文件工作面

主页右侧紧凑文件区是真实项目树和 Growth 观察入口：单击文件进入完整文件工作面，单击文件夹只展开/折叠文件夹。Growth 运行时，真实层级中显示正在创建、正在修改、负责 Agent、锁定、等待和失败状态。

完整文件工作面包括文件树、文档编辑区和文件详情。默认直接编辑排版后的所见即所得内容，Markdown 源码是可切换的辅助视图。裸按 `Alt` 与 Windows 菜单行为冲突，不采用；讨论中建议 `Ctrl+Shift+M`，但正式快捷键仍需在实现前完成全局冲突检查。

保存采用自动保存：停止输入后自动保存，`Ctrl+S` 立即保存，连续输入合并为合理的撤销单位；保存失败保留本地草稿。支持经典撤销/重做。被 Growth 真实锁定的文件在所有视图中只读。

### 3.6 世界工作面与 Atlas

“世界”不是单张地理图，而是整个设定体系，包括地理、国家/组织、文明/族群、历史/事件及其关系。非地理内容采用“分类总览 + 统一 Entity Sheet（实体档案）”，不同类型显示各自字段。

地图采用 Atlas Scene（图册场景）体系，而不是要求一张图无限缩放：

- 支持世界、大陆、王国、城市、室内等层级。
- 支持星系、恒星系、行星等科幻层级。
- 支持多世界或无限宇宙的图结构。
- 每个场景可以使用独立生成的底图，并叠加结构化可交互图层。
- 世界结构和 Canon 先于图片建立，不从任意 AI 图片反推全部事实。
- 场景间通过面包屑和语义缩放导航。
- 单击选中；双击、`Enter` 或明确按钮进入子场景；滚轮只缩放当前场景。

### 3.7 角色工作面

角色页以文字档案为主，使用连续的长档案阅读与编辑，不把内容切成大量标签页。页头可放一张较小主图，更多图片按需展开画廊。创作者视角可以看到角色秘密；玩家视角的可见边界仍由领域规则决定。

### 3.8 图谱工作面

图谱首先是供 AI 和用户快速查询世界事实与因果关系的底层投影，其次才是视觉展示。权威分层保持：

```text
完整文档/来源 -> Canonical Assertions（权威断言） -> 图谱投影 -> AI 查询与用户界面
```

不强制使用专用图数据库。图谱页面分为世界关系、因果链和 Growth 执行三个语义不同的视图，不把它们混成一张图。

用户视图采用局部聚焦的神经元节点图，而不是一次加载整个世界。顶部既可搜索实体，也可使用自然语言询问因果。单击节点查看旁侧详情和相关内容；双击使节点居中并展开邻域；明确按钮进入完整实体档案。拖动节点只改变视觉位置，不改变事实；关系边可查看来源和证据。

这里讨论中的“玩家”指 NovelX 的普通使用者，不代表 Player Lens（玩家视角）。

### 3.9 故事工作面

故事采用卷、章、场景层级：场景是最小编辑单元；章节支持连续阅读和编辑；卷按需加载章节。故事同时具有正文与结构化事件链：

- `正文` 与 `事件链` 是同一故事的两个子视图。
- 故事事件被拆为清晰因果链，并可与世界历史相连。
- 世界历史可以脱离任何故事独立存在。
- 故事页呈现局部事件链，全局图谱负责跨故事和世界历史查询。
- AI 提议的事件先是草稿，经规则或用户确认后才进入正式事实。

### 3.10 世界包工作面

世界包是完整项目的封面、简介、总览、校验和打包中心，不是普通导出弹窗，也不是只读发布页。接收者用 NovelX 打开世界包文件夹后，应像原作者一样继续编辑自己的副本；默认不与原作者自动同步。

封面使用一份高分辨率主资产，并保存竖版、方形和横版的非破坏性裁切；项目方块使用方形裁切。

默认导出完整、干净、可编辑的世界内容，不允许逐文件或逐领域对象取消勾选，避免制造残缺包。打包清单的勾选符号表示校验通过，不是内容选择。

无论选择何种打包方式，都必须排除凭据、权限状态、系统内部文件、机器绝对路径、缓存和临时锁。可选附加项包括：

- 会话记录，默认关闭；仅包含清理后的用户可见记录。接收者继续时创建新会话或分支，不恢复原机器上的精确运行时。
- 整个项目目录；仍需安全过滤，不是危险的逐字节备份。
- 模型与生成信息。
- 项目扩展，包括 `agent.md` 和用户自制 Skill（技能），默认关闭。

接收方导入 Agent 或 Skill 时不能自动启用，必须经过信任审查并允许保持禁用。工具使用记录通常随会话记录保存，不单设工具勾选项。内部 JSON 或 `.novelx` 数据对技术用户可能可见；“隐藏文件”不是安全边界。只读发布包若未来需要，应作为另一种产品定义。

### 3.11 图片归属

图片不再拥有独立的第七资源页，而是归属于地点、角色、组织、场景、故事或世界包。每个对象支持一张主图和图片画廊。Growth 生成的图片先作为候选，不自动替换主图；由用户或主编确认采用。图片生成状态必须与文字保存状态分开显示，共用资产引用，不复制同一图片文件。

### 3.12 Growth、Plan 与协助/自由

底部始终保留“协助 / 自由”。Growth 不是底部模式切换，也不是第七个资源图标；正式命令是 `/growth`。启用后，在对话输入区附近显示“（生长）”状态。Plan 对应 `/plan` 和“（计划）”状态。

正常创作流程是用户先与 AI 深入讨论，AI 再填充四个核心内容骨架：世界、角色、图谱、故事；文件是存储和编辑入口，世界包是聚合与打包入口。Growth 用于用户只给较少目标时，约束 AI 持续思考并填充这些骨架，而不是让它无规则乱做。

`/plan` 只讨论方案，主动持续 Ask（询问）直到条件确认，不写项目；最后询问是否开启 Growth。一个会话同一时间只有一个 Growth；再次输入 `/growth ...` 是给当前 Growth 增加或调整指令，另开 Growth 需要新会话。即使当前是“协助”，`/growth` 也授予该 Growth 的范围内执行许可，但不改变全局协助/自由设置；高风险或范围外动作仍需询问。

Growth 状态至少显示：运行、暂停、等待、失败、完成。

### 3.13 Growth 的实时前端投影

Growth 不是 UI 动画。右侧文件树、各资源页和活动详情必须投影同一份真实 Runtime 状态。已讨论的文件生命周期是：

```text
分配 -> 运行时租约锁定 -> 流式草稿 -> 校验 -> 版本化 Change Set（变更集）
-> 原子提交 -> 解锁 -> 触发下游任务
```

不得把半截流式文本直接写成正式文件。正在编辑的文件由 Runtime 真锁定，所有编辑入口只读。

用户停止编辑后：进入取消中，保留部分草稿，向主编报告“用户停止了这段编辑”，主编询问用户停止原因，受影响分支等待用户选择恢复、重新分配、用户接管或取消。与该分支没有输入依赖的其他 Growth 执行叶可以继续；暂停分支的未提交内容不得成为其他分支的输入。

地理内容生长采用主编—执行叶结构：主编先注册完整地理骨架，再把每个已注册地形连同注册事实、父子包含、相邻关系、水系关系和世界题材摘要交给一个 `novelx-geography` 子 Agent。子 Agent 只能读取事实并返回一份完整地理草稿；不得写正式文件、派生 Agent、直接依赖其他子 Agent，或进入国家、文明、角色、故事和图片阶段。

子 Agent 返回后，草稿只向主编回传。主编负责核对事实、要求同一子会话返工或正式提交。主编审核期间目标文件继续锁定只读，只有正式提交成功后才解锁并成为可供后续阶段引用的世界事实。该阶段只有在每个已注册地形都有一份正式提交的详细文档后才能结束；“模型回答结束”和“骨架注册成功”都不是完成条件。地图在本阶段保持真实空状态，注册坐标不得被前端绘制成假地图。

### 3.14 视觉语言

- 暖色工作室氛围，但减少色彩数量。
- 图标使用一致的单色线性符号库。
- 主要通过层级、留白、细边界和字重区分状态，不依赖彩色按钮。
- Agent 行为使用符号和文本，不为每个 Agent 分配不同彩色按钮。
- 不使用套娃卡片、厚重窗口框或装饰性软件外壳。
- AI 概念图只决定视觉方向，不能替代交互、数据或运行时定义。

## 5. 尚未确认，完成已讨论骨架后继续逐项询问

以下内容不得由实施者自行补成产品决定：

1. 各栏精确默认宽度、最小/最大宽度和拖动吸附规则。
2. 宽屏、普通宽度、窄窗口的切换阈值，以及最小支持窗口尺寸。
3. 各类展开、收起、换页、覆盖层和详情栏动画的精确时长、缓动与中断行为。
4. 顶栏高度、图标尺寸、间距、边角、阴影、字体和完整 Design Tokens（设计令牌）。
5. 各工作面的完整工具栏、右键菜单、快捷键和冲突表。
6. 空状态、加载、错误、权限不足、锁定、离线、保存失败和恢复状态的详细视觉与交互。
7. 弹出菜单、对话框、Toast（轻提示）、图片查看器和批量操作。
8. `Ctrl+Shift+M` 是否最终作为排版/源码切换快捷键。

~~~~text
## 文件的真实生命周期

不能让模型直接把半截内容逐字写进正式文件。正确线路应是：

```text
Growth 分配任务
  ↓
Runtime（运行时）授予文件所有权
  ↓
Agent 写入 Streaming Draft（流式草稿）
  ↓
界面实时展示草稿，但正式文件保持稳定
  ↓

  ↓

  ↓
原子提交正式文件
  ↓
释放文件锁
  ↓

```

新文件在生成期间可以先以“创建中”的半透明节点出现在项目树里，但不能冒充已经保存。提交成功后才变成普通文件。

## 正在编辑的文件锁

用户要求“正在编辑的文件无法修改”是合理的，但必须是运行时锁，不能只是把编辑框设为灰色。

锁定期间：

- 用户只能查看、搜索和复制，不能修改、重命名或删除。
- 其他 Agent 也不能同时修改同一文件。
- 依赖该文件的 Agent 只能读取最后一次正式提交，不能读取半截草稿。
- 所有工作面都显示同一锁定状态。
- 文件顶部显示：`地理 Agent 正在编辑此文件`。
- 关闭页面或切换工作面不会解除锁定。

锁应采用 Lease（租约锁）机制：Agent 崩溃或 NovelX 异常退出后可以恢复或释放，不能永久把文件锁死。

## Growth 的运行状态

一个 Growth 至少需要这些真实状态：

```text
准备计划
→ 等待执行
→ Agent 工作中
→ 等待依赖
→ 等待用户决定
→ 验证结果
→ 提交文件
→ 完成 / 部分完成 / 失败 / 取消
```

“暂停”和“停止”也要分开：

- 暂停：不再派发新任务，正在生成的文件可以完成当前安全步骤。
- 停止：请求取消当前 Agent，进入“取消中”，不能瞬间假装已经停止。
- 单文件停止：只停止拥有该文件的 Agent，其他无关分支继续生长。
- 整体停止：停止整个 Growth，但保留已经正式提交的内容。

## 必须避免的假实现

- 根据文件时间戳猜测“哪个 Agent 修改了文件”。
- 只在前端禁用编辑，其他窗口仍然能够写入。
- 把模型流式输出直接写入正式文件。
- Agent 失败后仍显示“已完成”。
- 新文件刚出现就让下游 Agent读取半截内容。
- 页面关闭后 Growth 状态和文件锁一起丢失。
~~~~

~~~~text
## 不能从图片反推世界结构

最危险的路线是：

```text
先让 AI 随便画图
→ 再猜山脉、边境和城市在哪里
```

这只能作为辅助，无法成为稳定权威。

更可靠的顺序是：

```text
先生成结构化世界数据
→ 确定区域、邻接、方位和大致形状
→ 根据这些数据生成地图底图
→ 使用同一份结构生成交互图层
→ 用户或 Agent 校准少量偏差
```

也就是说，地图图片不是世界本身。世界结构才是权威数据，图片是它的一种视觉表现。

即使底图重新生成，地点和国家仍然有稳定 ID，不会因为新图片长得不一样就丢失全部关系。

## 地图层级怎么移动

不建议一开始追求一张图片从宇宙无限缩放到房间内部。那会要求所有层级共享连续坐标和统一画风，AI 图片很难保证。

更合理的是 Semantic Zoom（语义缩放）：

1. 在世界地图双击北境王国。
2. 地图平滑放大到北境边界。
3. 到达阈值后切换为“北境王国地图”。
4. 顶部出现路径：

```text

5. 返回上一级时恢复原世界地图的缩放和中心位置。

视觉上像连续深入，数据上是不同场景之间切换，所以每一级可以有完全不同的地图图片和比例。

| 题材 | 主画布 |
~~~~
