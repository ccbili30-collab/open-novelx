# NovelX 题材自适应世界生长设计

状态：已获产品确认，待实现与真实验收

日期：2026-07-19

## 1. 当前目标

在 OpenCode 内核改版中补回被地理专用链覆盖掉的前置步骤：Growth 主编先让真实 Provider（模型服务）判断当前题材的世界由哪些层面构成、每层需要注册多少实体以及层间依赖；随后按该蓝图逐层注册具体实体，交给固定的世界档案子 Agent 写作，由主编审核并提交，直到“世界”工作面中由模型选择的全部层面完成。

本轮使用科技题材做 Live（真实运行）验收，但正式能力不得写死科技、幻想、国家、种族、宗教或任何固定分类。

## 2. 产品边界

### 本批完成

- 模型自由决定世界层名称、用途、数量、依赖、推演重点和档案章节。
- Harness（智能体运行框架）生成稳定 ID、路径、顺序、哈希和状态，校验规模、拓扑、幂等和写入边界。
- 每层开始前向主编提供已提交前序事实；主编据此注册当前层的具体实体及关系。
- 每个具体实体由只读叶节点子 Agent 生成一份真实 Markdown 档案。
- 正式文件在主编提交前保持未创建或旧版不变，运行中的文档在 NovelX 桌面只读并展示真实流式输出。
- 世界页按模型注册的动态层显示蓝图、实体、进度、执行 Agent、锁和正式档案。
- `/growth` 仅在全部动态世界层、实体和档案提交后完成。

### 本批不做

- 不生成地图、星图、插画、封面或任何图片。
- 不进入角色、故事、图谱事实、世界包聚合和导出。
- 不接入或修改旧 NovelX Runtime（运行时）。
- 不修改 OpenCode 公共 HTTP 协议、Session V2、数据库 Schema（数据合同）或 Provider 协议。
- 不把科技题材的本轮结果固化为模板或默认分类。

## 3. 权威数据分层

新增两份独立、可校验的内部权威文件，不覆盖现有地理 Live 证据：

```text
.novelx/growth/world-blueprint.json
.novelx/growth/world-materialization.json
```

`world-blueprint.json` 只保存主编模型决定的道路：世界标题、题材、尺度、设计摘要，以及自由命名的层面。每个层面包含用途、目标实体数、对更早层面的依赖、可检查的推演重点和档案章节。Harness 不维护“国家/种族/宗教必须存在”的枚举。

`world-materialization.json` 保存逐层注册和物化状态：当前层注册的具体实体、实体间关系、对已提交前序实体的依赖、目标路径、租约、子会话、草稿与提交哈希、失败和等待用户状态。

现有 `.novelx/growth/skeleton.json` 与 `geography-materialization.json` 作为已完成地理批次的兼容读取路径保留；新的 `/growth` 不再写入这两份旧合同。

## 4. 模型与 Harness 的职责

### 模型负责

- 根据用户目标决定世界需要哪些层面；允许没有国家、种族或宗教，也允许出现企业联盟、轨道设施、自治 AI、技术范式或其他自定义层面。
- 决定每层适合注册多少实体，说明该层用途、依赖和推演重点。
- 在当前层开始时读取 Harness 提供的前序正式事实，注册具名实体、最小事实、约束、前序依赖和同层关系。
- 审核子 Agent 是否遵守当前层合同，而不是按个人文风反复返工。

### Harness 负责

- 限制层数、单层实体数、总实体数、章节数和文本长度。
- 保证层依赖只指向更早层，实体依赖只指向已提交的前序实体。
- 拒绝空话、编号占位名、空事实、重复实体、未知依赖和不安全 Windows 路径。
- 生成稳定 ID、正式路径、草稿路径、完整性哈希和状态迁移。
- 保证注册、准备、提交、停止和完成操作幂等或失败关闭。
- 只允许绑定的 Growth 主编和其拥有的固定世界子会话发布正式档案。

## 5. 运行线路

```text
用户输入 /growth <世界目标>
  → Growth 主编调用 novelx_register_world_blueprint
  → Harness 持久化动态世界蓝图
  → 对每个蓝图层按拓扑顺序：
      → novelx_prepare_world_stage 返回蓝图要求与已提交前序事实
      → 主编调用 novelx_register_world_stage 注册具名实体和关系
      → 对该层每个实体：
          → novelx_prepare_world_document 获取租约与 Context Pack
          → task(subagent_type=novelx-world-writer)
          → 世界子 Agent 根据真实事实与约束输出档案
          → 主编检查章节、来源和占位内容
          → novelx_commit_world_document 原子提交正式文件
      → 下一层只能在依赖层全部提交后开始
  → novelx_finish_world 校验全部蓝图层、实体和档案
  → 桌面世界页显示完成；图片继续为空
```

固定的跨题材档案底线只有 `事实依据` 与 `因果推演`。其余章节由主编在蓝图中针对该层决定，例如科技组织可以要求“组织结构、运作机制、资源与影响、风险与边界”，天体层可以要求“空间结构、物理环境、资源与通行、风险与边界”。

## 6. 失败、停止与恢复

- Provider 缺失：不创建蓝图，失败关闭。
- 蓝图非法：不创建任何世界实体或正式文件，允许模型在当前回合修正。
- 当前层依赖未完成：拒绝注册该层。
- 实体引用未知或未提交前序事实：拒绝注册。
- 子 Agent 输出缺章节、越过事实边界、含占位内容或长度非法：拒绝提交；主编可对同一子会话做一次有明确原因的修订。
- 用户停止某个实体：保存绑定子会话并进入 `waiting_user`，释放租约；主编向用户报告“用户停止了这段编辑”并询问原因。
- 同层其他独立实体可以继续；依赖该层的后续层不得开始。
- 项目重开：桌面从两份权威文件和正式档案恢复，不依赖会话内存。
- 文件损坏、未知版本或哈希不符：桌面显示明确错误，不回退到模板。

## 7. 验收标准

1. 科技题材 Live 中，世界层名称与组合来自真实模型，代码和测试没有固定要求国家、种族或宗教。
2. 主编先注册完整世界蓝图，再按层注册具体实体；不存在一开始生成编号空槽位的行为。
3. 每层注册都能证明读取了前序已提交事实；每份档案包含事实依据与可检查的因果推演。
4. 每个正式文件来自唯一的真实 `novelx-world-writer` 子会话，并由 Growth 主编提交。
5. NovelX 桌面真实显示动态层、实体进度、流式草稿、文件锁、正式档案和总完成状态。
6. 图片、角色、故事、图谱事实和世界包不产生副作用。
7. 缺失 Provider、非法拓扑、错误依赖、重复调用、不同规格覆盖、损坏状态和提前完成全部失败关闭。
8. Schema、OpenCode、App、Desktop 的相关测试、类型检查和生产构建通过；真实 Electron 打开同一 Live 项目验收。

## 8. 停止条件

- 必须修改 OpenCode 公共协议或冻结的 Session V2 才能继续。
- 只能用固定题材模板、Fixture（测试夹具）或本地规则替代真实模型注册。
- 无法把世界子 Agent 限制为只读叶节点，或无法保证正式提交门禁。
- 真实 Provider 不可用，无法形成科技题材完整世界 Live。
- 实现必须进入图片、角色、故事或图谱阶段才能宣称世界项完成。
