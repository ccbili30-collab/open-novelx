# NovelX Growth 自动骨架注册设计

状态：本阶段已实现并完成真实 Provider 与 Electron 验收

日期：2026-07-19

## 1. 当前目标

在 OpenCode 内核改版上闭合 `/growth` 的第一个真实阶段：模型先根据用户目标完成内部自询，只提交一个有界的 `GrowthSkeletonProfile`（生长骨架规格）；Harness（智能体运行框架）随后确定性编译并持久化六个 NovelX 工作面的待填充骨架。

本阶段只注册“后续 AI 应沿哪些道路生长”，不生成天文、地理、国家、文明、角色、关系或章节正文。

## 2. 明确不做

- 不接入旧 NovelX Growth Runtime（运行时）。
- 不把静态 Fixture（测试夹具）或关键词分类冒充模型判断。
- 不创建国家、角色、关系或故事事实。
- 不生成地图、立绘、封面或其他图片。
- 不把待填充槽位标记成已完成文件或 Canon（正史）。
- 不在这一批设计 Growth 的后续修订、暂停、恢复和多 Agent 填充阶段。
- 不新建第二套数据库；项目目录仍是可携带权威载体。

## 3. 产品语义

### 3.1 模型负责什么

模型只能决定：

- 题材族与用户可读题材标签。
- 世界尺度。
- 世界需要注册哪些层面以及每层多少待填充槽位。
- 角色需要哪些功能组以及每组多少待填充槽位。
- 图谱需要哪些查询/观察视图。
- 标准空章节数量。

模型不能决定文件路径、内部 ID、Schema（数据合同）版本、完成状态、写入方式或安全边界。

### 3.2 Harness 负责什么

Harness 必须：

- 验证模型输出的形状、范围、唯一性和总规模。
- 生成稳定 ID、排序和标准章节名。
- 从四个核心骨架派生文件与世界包投影。
- 一次注册一个权威 Manifest（清单）。
- 对完全相同的重放返回既有结果。
- 对不同规格的覆盖尝试失败关闭。

### 3.3 六个工作面的含义

| 工作面 | 注册内容                         | 是否是正式内容           |
| ------ | -------------------------------- | ------------------------ |
| 文件   | 后续将物化的目录/文件路径规划    | 否，显示为待创建         |
| 世界   | 题材适配后的世界层面与槽位       | 否，显示为待填充         |
| 角色   | 功能组与角色槽位                 | 否，显示为待填充         |
| 图谱   | 空图谱的查询/观察视图            | 否，不创建事实节点或关系 |
| 故事   | 一个故事根与平铺的标准空章节     | 否，不提前分卷或分主题   |
| 世界包 | 封面槽位、简介和总览区的聚合规划 | 否，显示为尚未完成       |

故事只有在正文真实形成后，才允许按主题、篇章或卷重新分组。骨架注册阶段只能产生 `第001章`、`第002章` 这类标准章节标识。

## 4. 权威清单

权威文件固定为：

```text
.novelx/growth/skeleton.json
```

原因：OpenCode 当前 `FileMutation`（文件变更）代码明确把多文件事务与崩溃恢复列为待设计事项。首次注册若同时创建大量空文件，无法诚实保证原子闭环。单一清单可以一次写入、严格校验、重开恢复，并让后续 Agent 按槽位逐步物化真实文件。

清单包含：

- `schemaVersion`。
- 注册来源会话与工具调用身份。
- 用户目标的哈希，而不是隐藏推理文本。
- 题材与尺度。
- 四个核心骨架。
- 派生的文件与世界包投影。
- Harness 生成的稳定标识、排序和状态 `planned`。
- 整体内容哈希。

清单不得包含原始思维链、Provider 凭据、系统指令或未经清理的工具输出。

## 5. `/growth` 运行线路

```text
用户输入 /growth <目标>
  → OpenCode 选择内置 Growth Agent
  → 真实 Provider 执行一次受限规划回合
  → 模型内部自询题材、尺度、层面和数量
  → 模型唯一终态调用 novelx_register_growth_skeleton
  → 工具验证并确定性编译
  → 幂等写入 .novelx/growth/skeleton.json
  → 文件监听事件刷新 NovelX 工作台
  → 对话显示生长规格摘要
  → 六个工作面显示同一清单的待填充投影
```

Growth Agent 首阶段只能读取项目并调用骨架注册工具；不得使用通用写入、编辑、补丁、Shell（命令行）、Task（子任务）或图片工具。没有可用 Provider 时沿 OpenCode 现有模型解析路径失败关闭，不能本地生成模板清单。

## 6. 题材适配

题材差异由模型输出的世界层面体现，而不是由 Harness 用关键词猜测。例如：

- 中世纪幻想可注册天文、地理、生态、国家、文明、组织、魔法等层面。
- 科幻可注册宇宙结构、星域、星系、行星、政体、文明、组织、技术等层面。
- 都市题材可注册城市、城区、机构、社群、行业、组织等层面。
- 无限流可注册主世界、任务世界类型、跨世界规则、组织和关卡等层面。

Harness 只验证层级是有限无环结构、数量处于上限内、标签非空且同级不重复；不把上述示例写死成唯一合法答案。

## 7. 失败与恢复

- Provider 不可用：不创建清单。
- 模型未调用唯一终态工具：不创建清单。
- 规格非法或超限：工具失败，允许模型在同一受限回合纠正。
- 清单不存在：六页显示原有空状态。
- 清单损坏或版本未知：六页显示明确错误，不能回退成默认模板。
- 同一规格重放：返回既有注册结果，不重复创建。
- 不同规格覆盖：返回冲突；本阶段不静默改写既有骨架。
- 项目重开：从清单恢复六页，不依赖会话内存。

## 8. 验收标准

完成本批必须同时证明：

1. `/growth` 出现在真实命令列表并走真实 Session（会话）命令链。
2. Growth Agent 只获得读取与唯一注册工具。
3. 中世纪幻想与科幻输入可产生不同世界骨架，而章节仍为标准空章节。
4. 清单通过共享 Schema 校验，且六个工作面都由它投影。
5. 重放幂等，不同规格覆盖失败关闭。
6. 损坏清单显示错误，不出现本地模板降级。
7. 重开项目后骨架仍存在。
8. 没有 Provider 时不产生任何伪注册结果。
9. 定向测试、App 与 OpenCode 类型检查、生产构建通过。
10. 使用真实 Provider 完成一次 `/growth` 注册并在桌面 UI 查看六页；若本机没有可用配置，必须明确记录未完成，不能用 Mock 代替。

## 9. 停止条件

出现以下任一情况立即停止扩展：

- 必须修改 OpenCode 公共 HTTP 协议才能读取清单。
- 必须新增多文件事务才能保证首次注册语义。
- 必须把待填充槽位伪装成真实文件或正式世界事实。
- 现有 Session/Agent/Tool 权限无法把 Growth Agent 限制到唯一写入工具。
- 实现需要改动旧 NovelX Runtime。
